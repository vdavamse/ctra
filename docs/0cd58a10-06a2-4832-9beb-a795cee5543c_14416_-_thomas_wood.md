## Abstract

A large proportion of clinical trials end without delivering results useful for clinical, policy, or research decisions -- a problem called "uninformativeness." Some high-risk indicators of uninformativeness can be identified at the stage of drafting the protocol, but the necessary information can be hard to find in unstructured text documents. The authors developed a browser-based tool that uses natural language processing (NLP) to identify and quantify the risk of uninformativeness. The tool reads and parses trial protocol PDFs, identifies key features of the trial design, and feeds them into a risk model. On a manually tagged dataset of 300 protocols, the tool achieved: condition identification with 100% AUC, SAP presence/absence with 87% AUC, effect estimate with 95% AUC, number of subjects with 69% accuracy, and simulation with 98% AUC. On 11,925 ClinicalTrials.gov protocols: phase with 75% accuracy, number of arms with 58% accuracy, countries with 87% AUC. The tool is focused on HIV and tuberculosis trials but could be extended to more pathologies.

## Problem Statement

The majority of clinical trials do not prove or disprove a hypothesis. A 2022 study by Hutchinson et al. found that just over a quarter of 125 clinical trials in heart disease, diabetes, and lung cancer ended informatively. Following Zarin et al. (2019), for a trial to be informative it must: (1) address an important unresolved question, (2) be properly designed, (3) be feasible, (4) be conducted and analyzed validly, and (5) report results accurately and promptly. The most common reason for uninformativeness is underpowering (inadequate sample size), followed by safety and commercial factors.

At the protocol-drafting stage, risk indicators of uninformativeness can be identified (e.g., small sample size, lack of statistical analysis plan, non-standard endpoints, cluster randomization). However, finding this information in unstructured protocol documents is time-consuming and error-prone. No existing automated tool used NLP to extract risk factors from trial protocols prior to this work.

## Key Contributions

1. **Novel NLP-based risk assessment tool** -- the first automated tool using NLP to extract risk factors for uninformativeness directly from clinical trial protocol PDFs.
2. **Eight-feature extraction pipeline** -- extracts pathology, trial phase, SAP presence, effect estimate, sample size, number of arms, countries of investigation, and simulation use from unstructured protocol text.
3. **Linear risk scoring model** -- a weighted linear formula (expert-derived weights) that converts extracted features into a 0-100 risk score with HIGH/MEDIUM/LOW classification.
4. **Open-source browser-based application** -- deployed as a web tool with interactive GUI, drag-and-drop PDF upload, visual explanations, and exportable reports.
5. **Feature importance survey** -- conducted qualitative survey of BMGF subject matter experts to prioritize which protocol features most influence uninformativeness risk.
6. **Dual-dataset validation** -- validated on both a manually tagged dataset of 300 protocols and 11,925 protocols from ClinicalTrials.gov.

## Methodology/Architecture

### System Architecture
- **Frontend:** Plotly Dash (Python) web application running in any browser
- **Backend:** Python server with NLP/ML logic connecting to a Java-based Apache Tika server for PDF parsing
- **Deployment:** Docker container; accessible at https://app.clinicaltrialrisk.org
- **Authentication:** Auth0.com for optional user accounts to save configurations

### Feature Extraction Models

| Feature | Technique | Details |
|---------|-----------|---------|
| Pathology (HIV/TB/Other) | Naive Bayes (3-class) | Whole-document token-level classification |
| Trial Phase | Ensemble: CNN (spaCy) + rule-based + Random Forest | Outputs probability array; max likelihood selected |
| SAP Presence | Naive Bayes | Whole-document word-level; page-level highlighting |
| Effect Estimate | Rule-based (spaCy) + weighted Naive Bayes | Identifies numeric candidates in 20-token windows |
| Sample Size | Rule-based (spaCy) + Random Forest | Identifies numeric candidates, ranks by likelihood; handles "per arm" modifiers |
| Number of Arms | Ensemble: spaCy + scikit-learn Random Forest | Rule-based and ML combination |
| Countries | Ensemble: regex + Keras CNN + Random Forest + Naive Bayes | Dictionary lookup with contextual disambiguation |
| Simulation | Naive Bayes (page-level) | Per-page classification; any positive page flags the protocol |

### Linear Risk Model Formula

```
score = 26*SAP + 16*effect_estimate + 10*sample_size_tertile + 10*international + 10*simulation + 5*phase + 2*arms - 7
```

- Score >= 50: LOW risk
- Score 40-49: MEDIUM risk
- Score < 40: HIGH risk

Weights were derived through qualitative expert consultation, not a loss function. SAP presence is by far the strongest predictor (weight = 26).

### Sample Size Tertiles
Sample sizes are converted to tertiles (0, 1, 2) based on comparisons to reference distributions by phase and pathology (HIV vs. TB). Default thresholds derived from 21 LMIC trials, adjusted with ClinicalTrials.gov statistics.

### Workflow
1. User uploads protocol PDF (drag-and-drop or file selector)
2. Server parses PDF to plain text via Apache Tika
3. NLP models extract 8 features
4. Features fed into linear risk model
5. Risk level displayed as color-coded traffic light (HIGH/MEDIUM/LOW)
6. User can manually correct extracted values
7. Export risk assessment to Excel or PDF report

## Datasets

| Dataset | Size | Source | Usage |
|---------|------|--------|-------|
| Manual dataset | 300 protocols | BMGF-supplied + ClinicalTrials.gov | Hand-annotated with key features; 100-300 labels per parameter |
| ClinicalTrials.gov AACT | 11,925 protocols | AACT data dump (4 Nov 2022) | Larger-scale validation with metadata (NCT ID, phase, pathology, SAP, arms, subjects) |
| Hutchinson et al. dataset | 6 protocols (of 125) | ClinicalTrials.gov | Risk model validation against informativeness outcomes |

**Training/validation split for ClinicalTrials.gov:** NCT IDs with 3rd digit 0-7 for training, 8 for validation, 9 held out as future test set.

## Results

### Manual Dataset Validation

| Component | Accuracy | AUC | Technique |
|-----------|----------|-----|-----------|
| Condition (Naive Bayes) | 88% | 100% | Naive Bayes |
| SAP (Naive Bayes) | 85% | 87% | Naive Bayes |
| Effect Estimate | 73% | 95% | Rule-based + Naive Bayes |
| Number of Subjects | 69% (71% within 10%) | N/A | Rule-based + Random Forest |
| Simulation | 94% | 98% | Naive Bayes |

### ClinicalTrials.gov Validation

| Component | Accuracy | Baseline (Naive Bayes) | Technique |
|-----------|----------|----------------------|-----------|
| Phase | 75% | 45% | Rule-based + Random Forest |
| SAP | 82% | 82% | Naive Bayes |
| Number of Subjects | 13% | 6% | Rule-based + Random Forest |
| Number of Arms | 58% | 52% | Rule-based + Random Forest |
| Countries | AUC 87% | N/A | Rule-based + CNN + RF + NB |

### Hutchinson et al. Validation
On 6 protocols from the Hutchinson et al. dataset, the tool predicted informativeness with 100% AUC (the two trials scoring 60 or below were both non-informative). However, this test set was acknowledged to be too small for scientific rigor.

### Key Findings
- SAP presence/absence is the strongest predictor of trial informativeness risk
- Sample size extraction was the most challenging task due to many confounding numbers in protocols
- Phase identification showed frequent confusion between Phase 2 and Phase 1/II
- Low sample sizes (10-30) were most prone to misidentification

## Limitations

1. **Domain restriction:** Currently trained only for HIV and TB trials; accuracy may decrease for other pathologies (e.g., oncology, cardiovascular) that depend on features not currently extracted (biomarkers, toxicity, chemotherapy cycles).
2. **Sample size extraction accuracy:** Only 13% accuracy on ClinicalTrials.gov data (though this is partly due to unreliable ground truth from the registry).
3. **Limited risk model validation:** Only 6 protocols could be located for informativeness outcome validation -- far too small for rigorous evaluation.
4. **Expert-derived weights:** The linear risk model weights were derived qualitatively rather than from data, potentially limiting generalizability.
5. **Single-document support:** Does not support protocols with SAP as a separate PDF.
6. **No formal user testing reported:** The peer reviewer noted the absence of systematic usability evaluation.
7. **Annotation process unclear:** The peer reviewer noted ambiguity in the annotation methodology and inter-annotator agreement.
8. **ClinicalTrials.gov ground truth quality:** Registry metadata is voluntarily provided and often inaccurate or outdated.

## Relevance to CTRA

This paper is the **most directly relevant** of the three to the CTRA project, as it is effectively CTRA's closest predecessor/companion:

- **Identical problem definition:** Both this tool and CTRA predict the risk of protocol uninformativeness -- not drug efficacy -- from protocol text. This paper explicitly defines and operationalizes "uninformativeness" as the target outcome.
- **Same input type:** Both systems take clinical trial protocol PDFs as input and extract structured features from unstructured text.
- **Feature overlap:** The features extracted (SAP presence, sample size, effect estimate, trial phase, number of arms, international scope, simulation use) are directly relevant to CTRA's risk model. The expert-derived feature importance ranking (Table 1) provides a prioritized list of features for CTRA to consider.
- **Risk scoring approach:** The linear scoring model with expert-derived weights provides a baseline approach that CTRA could build upon, potentially replacing expert weights with data-driven ones.
- **Open-source foundation:** The MIT-licensed codebase at https://github.com/fastdatascience/clinical_trial_risk provides a starting point for CTRA development.
- **Limitations as opportunities for CTRA:** The tool's weaknesses (limited to HIV/TB, poor sample size extraction, small validation set, no transformer-based models) represent concrete opportunities for CTRA to improve upon.
- **Zarin et al. framework:** The paper's adoption of the Zarin et al. (2019) five-condition framework for trial informativeness provides a shared theoretical foundation for CTRA.
