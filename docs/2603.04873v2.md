## Abstract

Accurate time series forecasting underpins decision-making in numerous domains, yet conventional ML development paradigms suffer from data scarcity in new deployment scenarios, poor adaptability under distribution shift, and diminishing returns from manual model iteration. SEA-TS (Self-Evolving Agent for Time Series Algorithms) is a framework that autonomously generates, validates, and optimizes forecasting algorithm code through an iterative self-evolution loop. The framework introduces three key innovations: (1) Metric-Advantage Monte Carlo Tree Search (MA-MCTS), which replaces conventional fixed rewards with a statistically normalized advantage score; (2) Code Review with running prompt refinement, where every successfully executed solution undergoes automated logical review followed by running prompt updates that persistently encode corrective patterns; and (3) Global Steerable Reasoning, which compares each evaluated node against global best and worst solutions, enabling cross-trajectory knowledge transfer. A MAP-Elites quality-diversity archive maintains architectural diversity. On the public Solar-Energy benchmark, SEA-TS achieves a 40% MAE reduction relative to TimeMixer.

## Problem Statement

1. **Reward hacking in LLM-based AutoML**: Agents optimizing metrics frequently produce code with logical flaws (e.g., data leakage in time series) that yield inflated scores but fail in deployment.
2. **Simplistic reward mechanisms**: Existing approaches use binary or fixed rewards (+1 for any improvement), failing to distinguish marginal gains from significant breakthroughs.
3. **Limited reasoning context**: Most agents reference only local information (parent/sibling nodes), lacking global awareness of best and worst solutions across search history.
4. **Static prompts**: System prompts remain fixed throughout search, missing opportunities for on-the-fly adaptation based on discovered failure modes.

## Key Contributions

1. **Metric-Advantage MCTS (MA-MCTS)**: Replaces fixed rewards with z-score normalized advantage: A_j = (mu(M) - M_j) / sigma(M), providing discriminative, adaptive, and metric-agnostic reward signals.
2. **Code Review with running prompt refinement**: Automated logical review of every non-buggy solution. Review findings distilled into a continuously evolving running prompt that prevents recurrence of identified issues.
3. **Global Steerable Reasoning**: Compares each node against global best (N*) and worst (N⊥) solutions, enabling cross-trajectory knowledge transfer and avoiding redundant exploration.
4. **MAP-Elites quality-diversity archive**: Maintains diverse elite solutions across architectural dimensions, preventing premature convergence to a single approach.
5. **Autonomous discovery of novel architectures**: The agent independently discovered physics-informed patterns (monotonic decay heads, per-station diurnal profiles) not present in any reference code.

## Methodology/Architecture

### Self-Evolution Loop (5 phases per iteration)

1. **Node Selection**: UCT formula: UCT(N_j) = Q_j/n_j + C * sqrt(ln n_parent / n_j)
2. **Prompt Assembly & Code Generation**: P_full = P_0 ⊕ P_run ⊕ Context(N_parent) ⊕ P_global(T) ⊕ P_archive(A)
3. **Sandbox Execution & Evaluation**: Execute generated code in sandbox; obtain metric M_j
4. **Code Review & Prompt Update**: For non-buggy nodes, automated review + global comparison → update running prompt P_run
5. **Tree Update**: Compute advantage, assign reward, backpropagate, update archive

### Metric-Advantage Reward (M-A-R-Q Chain)

```
M_j → A_j (standardize) → R_j (review) → Q_j (backprop)
```

- **Metric M_j**: Raw evaluation metric from sandbox execution
- **Advantage A_j**: Z-score: (mu(M) - M_j) / sigma(M) for lower-is-better metrics
- **Reward R_j**: -1 if buggy (code review flagged), else A_j
- **Q-value**: Cumulative backpropagated reward

### Code Review as Reward Hacking Prevention

Every non-buggy solution undergoes automated logical review checking for data leakage, look-ahead bias, and other time-series-specific violations. Buggy nodes receive R = -1 regardless of their metric performance.

### MAP-Elites Archive

Maintains a grid of diverse elite solutions indexed by architectural features (e.g., model family, feature engineering approach, loss function type). Sampled during prompt assembly to inject diversity.

## Results

- **Solar-Energy (public)**: 40% MAE reduction vs TimeMixer (MAE: 1.757 vs 2.929)
- **Proprietary Solar PV**: WAPE 17.12% vs TimeMixer 25.75% (-8.6% reduction)
- **Proprietary Load**: WAPE reduction of 7.7% vs Timer; MAPE 26.17% vs TimeMixer 29.34%
- **Novel architectural discoveries**: Agent autonomously discovered:
  - Monotonic Decay Head: Encodes physical law of solar irradiance decline after noon
  - Daily Cycle Residual: Per-station diurnal profiles with fractional hour interpolation
  - Diurnal Bias: Station embeddings + hour-of-day features for fine-grained bias correction
  - Period Experts: Multi-period aggregation (24h + 12h cycles)
- **Implementation**: GPT-5 (high reasoning effort) for code generation/review; 500 iterations budget; MAP-Elites archive with 343 cells

## Limitations

1. **Computational cost**: 500 iterations with sandbox execution (model training) per task; wall-clock time of days to weeks depending on model complexity.
2. **LLM dependency**: Requires powerful LLMs (GPT-5) for effective code generation and review.
3. **Domain-specific evaluation**: Validated only on energy time series forecasting; generalization to other time series domains not demonstrated.
4. **Code review heuristics**: Automated review may miss subtle logical flaws that a human expert would catch.

## Relevance to CTRA

SEA-TS is referenced in `README.md` as ref [24] and directly informs two MCTS improvements in CTRA:

1. **Error penalty R=-1**: CTRA's MCTS assigns a penalty reward (R=-1) for nodes that fail during feature computation, drawing from SEA-TS Equation 7 where buggy nodes (b_j = true) receive R_j = -1 regardless of their metric advantage. This prevents the search from revisiting failed feature engineering strategies.

2. **Reward hacking prevention via code review**: SEA-TS's automated code review mechanism (checking for data leakage, look-ahead bias) informs CTRA's approach to validating agent-proposed features. In clinical trials, "reward hacking" could manifest as features that leak outcome information (e.g., features derived from post-trial data).

3. **MAP-Elites quality-diversity archive**: SEA-TS's approach to maintaining diverse elite solutions across architectural dimensions is relevant to CTRA's Pareto multi-objective MCTS, which also aims to maintain diversity across the accuracy-parsimony frontier.

4. **MA-MCTS z-score normalization**: The z-score advantage mechanism for scale-agnostic rewards complements the UCT exploration paper (ref [31]) in providing principled reward normalization for CTRA's feature evaluation scores.
