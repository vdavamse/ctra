## Abstract

Recent advancements in large language models (LLMs) have shown remarkable potential in automating machine learning tasks. However, existing LLM-based agents often struggle with low-diversity and suboptimal code generation. While recent work (Chi et al., 2024) has introduced Monte Carlo Tree Search (MCTS) to address these issues, limitations persist in the quality and diversity of thoughts generated, as well as in the scalar value feedback mechanisms used for node selection. This study introduces Introspective Monte Carlo Tree Search (I-MCTS), a novel approach that iteratively expands tree nodes through an introspective process that meticulously analyzes solutions and results from parent and sibling nodes. This facilitates a continuous refinement of the node in the search tree. Furthermore, the authors integrate an LLM-based value model to facilitate direct evaluation of each node's solution prior to conducting comprehensive computational rollouts. A hybrid rewarding mechanism is implemented to seamlessly transition the Q-value from LLM-estimated scores to actual performance scores. Applied to various ML tasks, I-MCTS demonstrates a 6% absolute improvement in performance compared to strong open-source AutoML agents.

## Problem Statement

1. **Low-diversity code generation**: Existing LLM-based AutoML agents (AIDE, Data Interpreter, SELA) typically involve only a single pass or trial, limiting generation of diverse and highly optimized workflows.
2. **Suboptimal node expansion**: Standard MCTS expansion generates thoughts without analyzing why previous siblings succeeded or failed, leading to redundant exploration.
3. **Scalar-only feedback limitation**: Traditional MCTS rewards rely solely on development set performance scores, which are computationally expensive to obtain and provide no verbal/qualitative guidance for improvement.

## Key Contributions

1. **Introspective Node Expansion (INE)**: A novel expansion mechanism that generates child nodes by explicitly analyzing solutions and results from parent and sibling nodes, incorporating reflective reasoning and feedback about prior solutions.
2. **Hybrid Reward Mechanism (HRM)**: Combines LLM-estimated evaluations (predicting node potential through ML evaluation criteria) with actual performance scores, using an adaptive blending strategy that transitions Q-values from LLM-estimated to actual values across search iterations.
3. **6% absolute improvement**: Demonstrates superior performance over strong open-source AutoML baselines across 20 diverse tabular datasets.

## Methodology/Architecture

### Overall Framework

I-MCTS builds upon traditional MCTS with two key innovations integrated into the standard Select → Expand → Simulate → Backpropagate loop:

1. **Selection**: Standard UCT formula selects the most promising node for expansion.
2. **Introspective Expansion**: Given parent node x_parent and sibling nodes x_sibling, generates a new child node by:
   - Evaluating solutions σ_sol(x_parent) and σ_sol(x_sibling) via LLM
   - Identifying strengths, weaknesses, issues, and potential improvements
   - Generating fine-grained, stage-specific insight λ_new tailored to the current ML pipeline stage τ
   - Creating child node inheriting parent attributes plus refined insight
3. **Hybrid Reward Evaluation**: For each node x:
   - LLM value model M_value predicts estimated score s_LLM(x) based on ML evaluation criteria
   - After simulation, actual performance score s_actual(x) obtained from development set
   - Adaptive blending: Q(x) = α(x) · s_LLM + (1 - α(x)) · s_actual, where α decays with iterations
4. **Backpropagation**: Hybrid Q-value propagated up the tree

### LLM Agent Executor

The LLM agent handles the ML pipeline in stages: Data Preprocessing → EDA → Feature Engineering → Model Training → Model Evaluation. A state-saving mechanism caches stage code for each node, enabling code reuse across configurations.

- **20 tabular datasets** from AutoML Benchmark (AMLB) and Kaggle Competitions

## Results

| Method | Top1 Rate % | Avg. NS % ↑ | Avg. Best NS % ↑ |
|--------|------------|-------------|-------------------|
| AutoGluon | 5.0 | 53.2 | 53.2 |
| AutoSklearn | 25.0 | 46.1 | 47.5 |
| AIDE | 5.0 | 47.1 | 51.8 |
| Data Interpreter | 0.0 | 47.4 | 50.2 |
| SELA | 20.0 | 53.3 | 54.7 |
| **I-MCTS** | **45.0** | **58.6** | **59.8** |

- I-MCTS achieves the highest Top1 rate (45%) and average normalized score (58.6%)
- **Ablation results**: INE contributes +5.7% over SELA MCTS; HRM adds an additional +0.6% at r=10. At lower rollout budgets (r=5), HRM contributes +2.8%, confirming its value for efficient early exploration.
- Removing INE (I-MCTS w/o INE) only yields +0.2% over SELA MCTS, showing that introspective expansion is the primary driver of improvement.

## Limitations

1. **Computational overhead**: The introspective process introduces additional resource requirements from LLM calls for sibling/parent analysis, limiting scalability in resource-constrained scenarios.
2. **Evaluation scope**: Primarily focused on structured/tabular ML tasks. Effectiveness on heterogeneous data types (images, text, RL) remains unexplored.
3. **LLM value model reliability**: The LLM-estimated scores may not always correlate with actual performance, particularly for novel or domain-specific ML tasks where the LLM lacks training data.

## Relevance to CTRA

I-MCTS is directly cited in CTRA's MCTS design and referenced in `README.md` as ref [23]. Two key contributions inform CTRA's architecture:

1. **Introspective sibling analysis**: CTRA's MCTS expansion mechanism draws from I-MCTS's approach of showing the LLM what worked and failed in sibling nodes during feature engineering. This enables more targeted feature proposals in each MCTS iteration.

2. **Hybrid value model — rejected for CTRA**: I-MCTS's LLM-estimated scores transitioning to actual performance was evaluated but **rejected** for CTRA's biomedical use case (noted in README Supporting Research table). The concern is that LLM hallucination risk in biomedical feature evaluation could mislead the search toward clinically meaningless features. CTRA instead relies solely on actual XGBoost/TabPFN cross-validation scores for node evaluation.

The paper also validates the general approach of combining LLM agents with MCTS for AutoML — the same paradigm CTRA applies to clinical trial feature engineering.
