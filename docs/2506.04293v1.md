## Abstract

Clinical trials are critical for advancing medical treatments but remain prohibitively expensive and time-consuming. Accurate prediction of clinical trial outcomes can significantly reduce R&D costs and accelerate drug discovery. While recent deep learning models have shown promise by leveraging unstructured data, their black-box nature, lack of interpretability, and vulnerability to label leakage limit their practical use in high-stakes biomedical contexts. AUTOCT is a novel framework that combines the reasoning capabilities of large language models with the explainability of classical machine learning. AUTOCT autonomously generates, evaluates, and refines tabular features based on public information without human input. The method uses Monte Carlo Tree Search to iteratively optimize predictive performance. Experimental results show that AUTOCT performs on par with or better than SOTA methods on clinical trial prediction tasks within only a limited number of self-refinement iterations, establishing a new paradigm for scalable, interpretable, and cost-efficient clinical trial prediction.

## Problem Statement

Predicting clinical trial outcomes is important for reducing the $2.6B average cost and >10-year timeline of drug development. Two major paradigms exist: (1) classical ML with expert-curated tabular features (robust but limited to manual feature engineering), and (2) deep learning models that integrate unstructured multi-modal data (powerful but black-box, lacking interpretability, and vulnerable to label leakage when extracting information from external databases without enforcing knowledge cutoffs). The paper addresses the gap between these paradigms by proposing a framework that uses LLMs as autonomous feature engineering agents to construct interpretable tabular features, which are then used with classical ML models for transparent, quantifiable predictions.

## Key Contributions

1. **Novel generalizable framework** -- AUTOCT achieves competitive performance on clinical classification tasks with state-of-the-art methods by combining LLM-driven feature construction with classical ML.
2. **First end-to-end clinical ML framework with automatic LLM-based feature extraction** -- The system dynamically discovers features based on the scope of accessible data sources (ClinicalTrials.gov, PubMed) without human intervention, starting from only trial identifiers and outcome labels.
3. **Interpretability meets LLM reasoning** -- Combines the interpretability of classical machine learning (Logistic Regression, Random Forest, XGBoost) with the reasoning capabilities of LLMs, enabling transparent and quantifiable predictions suitable for high-stakes clinical decision-making. SHAP values provide per-prediction explanations.

## Methodology / Architecture

AUTOCT consists of six key components orchestrated through Monte Carlo Tree Search (MCTS):

### 1. Retrieval Tools
- Two local knowledge bases: **PubMed DB** (academic articles) and **NCT DB** (ClinicalTrials.gov records), embedded using PubMedBERT-based embeddings.
- Hybrid retrieval combining BM25 and embedding-based similarity.
- **Label leakage prevention:** Publication-date filters ensure all retrieved documents were publicly available before the start date of the trial being considered. NCT DB queries exclude trials that began after the target trial's start date.

### 2. Feature Proposer
- **Initializing Proposer** (first iteration):
  - *Zero-Shot Proposer:* Given only the task description, uses CoT reasoning to suggest generic features from parametric knowledge.
  - *Factor-Based Proposer:* Receives individual labeled training samples and uses ReAct-style reasoning with retrieval tools to identify contributing factors.
  - An LLM summarizer synthesizes outputs from both into a unified feature set.
- **Iterative Proposer** (subsequent MCTS iterations): Takes a recommendation from the Evaluator and generates a single proposal of type Add, Refine, or Remove.

### 3. Feature Planner
- Transforms high-level feature ideas into structured, executable plans with step-by-step instructions and explicit schemas using CoT reasoning.

### 4. Feature Builder
- **Feature Grouper:** Clusters related feature ideas for efficient context-window usage.
- **Feature Researcher:** Uses ReAct paradigm to perform tool-augmented reasoning, retrieving information from PubMed DB or NCT DB.
- **Feature Builder:** Uses CoT reasoning to convert retrieved evidence into structured values per the feature plan schema.

### 5. Model Builder
- Trains three classical ML models: Logistic Regression, Random Forest, and XGBoost on the derived tabular features.

### 6. Evaluator
- **Model-Based Evaluator:** Analyzes ROC-AUC, feature importance, and feature plans using CoT to identify gaps and propose improvements.
- **Error-Based Evaluator:** Receives a misclassified validation example, uses ReAct reasoning with retrieval tools to investigate reasons for incorrect prediction and propose feature modifications.
- Suggestions from both evaluators are aggregated and fed to the Iterative Proposer.

### 7. Monte Carlo Tree Search (MCTS)
- Each node represents a feature set state; each edge is a transformation (Add, Refine, Remove).
- Selection uses UCT criterion: `UCT(x) = q(x)/n(x) + alpha * sqrt(ln(n(x_parent))/n(x))` with alpha=1.0.
- Maximum 10 rollouts, maximum depth 10.
- Best feature set selected by validation performance.

### LLM Backbone
- **gpt-4o-mini** with temperature 0.
- Cost: approximately $150 per MCTS run on 100 train + 100 validation samples.

## Datasets

- **Primary:** Trial Approval Prediction task from **TrialBench** benchmark (Chen et al., 2024) -- 24,468 training and 6,215 test samples.
- **Subsampled:** 100 training, 100 validation, 100 test samples via stratified sampling (due to computational budget).
- **Additional tasks:** Patient Dropout, Mortality, and Adverse Event prediction from TrialBench, restricted to Phase I trials with max 5 MCTS rollouts.
- **Input:** Only NCT IDs (trial identifiers) and outcome labels; no pre-engineered features are provided to the agent.

## Results

### Trial Approval Prediction (Table 1)

| Model | Phase I ROC-AUC | Phase II ROC-AUC | Phase III ROC-AUC |
|-------|-----------------|------------------|-------------------|
| LR | 0.520 | 0.587 | 0.650 |
| RF | 0.525 | 0.588 | 0.663 |
| XGBoost | 0.518 | 0.600 | 0.667 |
| FFNN | 0.550 | 0.611 | 0.681 |
| HINT | 0.576 | 0.645 | 0.723 |
| SPOT | 0.660 | 0.630 | 0.711 |
| MMFusion | 0.782 | 0.771 | 0.741 |
| **AUTOCT** | **0.753** | **0.639** | **0.702** |

AUTOCT achieves the highest Phase I PR-AUC (0.710) and competitive ROC-AUC across phases, notably outperforming HINT and SPOT on Phase I.

### Other Clinical Tasks (Table 2, Phase I only)

| Task | MMFusion ROC-AUC | AUTOCT ROC-AUC |
|------|------------------|----------------|
| Patient Dropout | 0.723 | 0.711 |
| Mortality | 0.900 | 0.852 |
| Adverse Event | 0.874 | 0.831 |

AUTOCT is competitive on PR-AUC (outperforming on Patient Dropout: 0.795 vs. 0.691 and Adverse Event: 0.796 vs. 0.726).

### Impact of MCTS Rollouts
- Performance generally improves with more rollouts, though plateauing is observed, likely due to limited sample size (100 train/val).
- The trend confirms that MCTS-guided exploration discovers more informative features over iterations.

### Case Studies (SHAP Analysis)
- NCT00035360 (Phase III, PEG-Intron, HIV): Low approval probability (0.244); primary outcome measure and treatment duration were most influential.
- NCT00628680 (Phase III, Zuragen vs. Heparin): High approval probability (0.895); treatment duration and inclusion criteria count were key.
- NCT02698176 (Phase I, Birabresib, Solid Tumors): Low approval probability (0.197); trial design, location, route of administration, and eligibility strictness drove the prediction.

## Limitations

- **Limited retrieval sources:** Only ClinicalTrials.gov and PubMed are used, due to knowledge-cutoff concerns. This may restrict feature richness and variety.
- **No hyperparameter optimization:** Focus is on proof-of-concept; systematic tuning could improve accuracy.
- **Small sample sizes:** 100 train/100 val/100 test limits generalization. Different disease categories may require distinct feature sets that are hard to learn with so few samples.
- **MCTS constrained to feature space:** The Evaluator does not diagnose which pipeline component (Feature Researcher vs. Feature Builder) is responsible for underperformance.
- **Label leakage risk from LLM parametric knowledge:** While retrieval is date-filtered, the LLM's own training data may contain post-hoc trial information.

## Relevance to CTRA

AUTOCT is relevant to the CTRA project in several ways:

- **Automated feature engineering for protocol analysis:** CTRA aims to predict protocol uninformativeness. AUTOCT demonstrates that LLMs can autonomously propose and construct meaningful features from CT protocol text and external databases, without human feature engineering. This approach could be adapted for CTRA to automatically discover features predictive of protocol uninformativeness.
- **Interpretability-first design:** CTRA requires actionable insights about why a protocol might be uninformative. AUTOCT's use of classical ML with SHAP explanations provides the kind of transparent, per-prediction interpretability that would be valuable for flagging specific protocol design issues.
- **Label leakage awareness:** AUTOCT's explicit date-filtering for retrieval is an important methodological lesson for CTRA, where predicting uninformativeness must rely only on information available at the protocol design stage, not post-hoc outcomes.
- **MCTS-guided iterative refinement:** The idea of iteratively proposing, testing, and refining features via MCTS could be applied to CTRA's feature discovery process, especially when exploring which protocol elements (eligibility criteria, endpoint definitions, site selection) are most predictive of uninformativeness.
- **Different prediction target:** AUTOCT predicts trial approval (drug efficacy), while CTRA predicts protocol uninformativeness. The framework is generalizable to different prediction targets, as demonstrated by AUTOCT's application to Patient Dropout, Mortality, and Adverse Event tasks.
