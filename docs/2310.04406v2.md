## Abstract

LATS (Language Agent Tree Search) introduces a unified framework synergizing LLM capabilities in planning, acting, and reasoning. Inspired by Monte Carlo tree search (MCTS) from reinforcement learning, LATS employs LLMs as agents, value functions, and optimizers. Critically, LATS uses external environment feedback for deliberate, adaptive problem-solving beyond reflexive prompting. Evaluated on diverse domains (programming, HotPotQA, WebShop), LATS achieves 94.4% Pass@1 on HumanEval with GPT-4 and 75.9 average score on WebShop with GPT-3.5, demonstrating effectiveness and generality.

## Problem Statement

1. **Simple acting processes insufficient**: LLMs demonstrate strong reasoning but rely on greedy, reflexive acting, falling short as autonomous agents due to lack of deliberate planning.
2. **Limited reasoning paths**: Existing methods (CoT, ReAct) fail to consider multiple reasoning paths or plan ahead, despite having sampled trajectories.
3. **No external feedback integration**: Recent search-guided LLM works (ToT, RAP) enable planning but operate in isolation without incorporating external feedback that could improve reasoning.
4. **No unified framework**: No existing approach combines reasoning, acting, and planning with external feedback in a single coherent framework.

## Key Contributions

1. **LATS framework**: First unified framework combining reasoning, acting, and planning to enhance LLMs. Adapts MCTS from model-based RL to language agents, using text as the interface between all components.

2. **LM-based MCTS variant**: Deliberately constructs best trajectories from sampled actions, guided by LM heuristics. Enables flexible, adaptive problem-solving compared to reflexive prompting.

3. **External feedback + self-reflection integration**: LATS enhances model sensibility and enables learning from experience by incorporating environmental observations and self-reflection, surpassing reasoning-only search methods.

4. **Comprehensive evaluation**: Demonstrates versatility across diverse domains (programming HumanEval/MBPP, multi-hop QA HotPotQA, web navigation WebShop) with strong empirical results.

5. **Ablation analysis**: Demonstrates necessity of every LATS component (MCTS search, LM value function, self-reflection, external environment) for optimal performance.

## Methodology/Architecture

### LATS Architecture Overview

LATS consists of six sequential operations applied iteratively until task completion or computational budget exhaustion:

#### 1. Selection
- Uses UCT (Upper Confidence bounds applied to Trees) algorithm to balance exploration/exploitation
- UCT formula: `UCT(s) = V(s) + w * sqrt(ln N(p) / N(s))`
- Where V(s) = value function, N(s) = visit count, w = exploration weight, p = parent node
- Starts from root, traverses tree level-by-level selecting highest UCT child until leaf reached

#### 2. Expansion
- Samples n actions from LM agent p_θ conditioned on current state
- Each action receives environment feedback (observation)
- Creates n new child nodes in tree
- Tree stored in external long-term memory

#### 3. Evaluation
- Assigns scalar value to each new child node for selection/backpropagation
- Repurposes p_θ as value function via prompting for reasoning about state
- LM instructed to end reasoning with score (0-10) indicating trajectory correctness
- Offers flexibility over programmed heuristics, efficiency over learned heuristics

#### 4. Simulation
- Expands currently selected node until terminal state
- At each depth, samples and evaluates nodes, prioritizing highest-value nodes
- Terminal state provides objective feedback on trajectory correctness
- If successful, LATS terminates; if partial/unsuccessful, proceeds to reflection

#### 5. Backpropagation
- Updates node values based on trajectory outcome
- For each node s_i in path: N(s_i) = N_old(s_i) + 1, V(s_i) = [r + N_old(s_i)*V_old(s_i)] / N(s_i)
- Where r = return from trajectory
- Updated values guide UCT selection for next exploration

#### 6. Reflection
- Upon failed trajectory, LM prompted with trajectory + final reward
- Generates verbal self-reflection summarizing errors and proposing alternatives
- Failed trajectories and reflections stored in external memory
- Subsequent iterations integrate reflections as context to agent and value function
- Enables in-context learning without expensive optimization (e.g., RL)

### Agent Formulation

- **Action space**: A = A ∪ Z (permissible actions + reasoning traces)
- **Observation space**: O (environment feedback)
- **Policy**: π(a_t | x, o_{1...i-1}, a_{1...i-1})
- **Initialization**: p_θ (pretrained LLM, leveraging useful representations)

### Advantages of LATS Framework

1. **Generality**: Supports both reasoning and decision-making via shared thought/action space
2. **Deliberate search**: MCTS + LM value function enable principled search selecting high-value options while exploring promising alternatives
3. **Adaptability**: External feedback + self-reflection enable greater adaptation during problem-solving
4. **Flexibility**: Accommodates different scenarios, environments, resource constraints via state design/tree dimensions
5. **Modularity**: Base agent, reflection generator, value function independently alterable

## Datasets

**Programming**:
- **HumanEval**: 164 handwritten Python programming problems, function signature + docstring + reference implementation + ~7.7 unit tests per problem
- **MBPP**: 974 short Python functions crowdsourced, 3 test cases per problem, avg 6.8 lines of code

**Question Answering**:
- **HotPotQA**: 113k Wikipedia-based QA pairs requiring multi-hop reasoning over 2+ supporting documents. Crowdworkers ensure diversity, multi-hop nature, explainability. Test subset: 100 questions

**Web Navigation**:
- **WebShop**: E-commerce environment with 1.18M real Amazon products across 5 categories, 113 subcategories, 12k human instructions, 800k+ product customization options. Text avg 262 words, vocab 224k. Metrics: Task Score (100 × avg reward), Success Rate (portion where r=1)

## Results

### HotPotQA Results (Table 2)

**Reasoning-based prompting** (CoT-only):
- LATS (CoT): 60% EM (competitive with reasoning-only search ToT 55%, RAP 60%)
- LATS (CoT + ReAct hybrid): **71% EM** (highest overall)

**Acting-based prompting** (with environment API):
- ReAct: 32% EM
- Reflexion: 51% EM
- **LATS: 61% EM** (2.0x performance of ReAct, 10 points over Reflexion)
- Effect of node expansion: LATS(n=3): 56%, LATS(n=10): 64%

### Programming Results (Table 3)

**HumanEval (Pass@1)**:
- GPT-3.5:
  - CoT: 46.9%
  - ReAct: 56.9%
  - Reflexion: 68.1%
  - ToT: 54.4%
  - RAP: 63.1%
  - **LATS: 83.8%** (47% improvement over Reflexion)
  
- GPT-4:
  - I/O baseline: 80.1%
  - Reflexion: 91.0%
  - **LATS: 94.4%** (SOTA, 3.4 points over Reflexion)

**MBPP (Pass@1)**:
- LATS: 81.1% (vs. RAP 71.4%, best prior baseline)

### WebShop Results (Table 4)

- ReAct: 53.8 score / 28.0% SR
- Reflexion: 64.2 score / 35.0% SR
- IL (imitation learning): 59.9 score / 29.1% SR
- IL+RL (reinforcement learning): 62.4 score / 28.7% SR
- **LATS: 75.9 score / 38.0% SR** (surpasses RL, 11.7 points over Reflexion)
- Expert human: 82.1 score / 59.6% SR

### Ablation Studies (Table 5, HotPotQA with ReAct base)

Impact of LATS components (50 trajectories):
- ToT(ReAct): 39% EM (DFS baseline)
- RAP(ReAct): 54% EM (MCTS without environment)
- LATS (No LM Heuristic): 37% EM (UCT without value function, dramatic -0.24 drop)
- LATS (DFS instead of MCTS): 42% EM (-0.08 vs. LATS with MCTS)
- LATS (No Reflection): 56% EM (-0.05 drop)
- **LATS (full): 61% EM** (all components essential)

**Self-reflection importance**: 0.05 drop when removed (smaller gain than Reflexion on ReAct), suggesting overlap between search benefits and reflection improvements.

**Token cost**: LATS same sample complexity O(kn) as ToT/RAP; lower token cost due to higher success rates and fewer failed trajectories.

## Limitations

1. **Higher computational cost**: Tree search requires more time and inference than simpler methods (ReAct, Reflexion). Mitigation: vary n (expansion nodes) for performance-efficiency tradeoff.
2. **Relatively simple benchmarks**: HotPotQA, HumanEval, WebShop are simpler than real-world complexity; some environments don't support rollbacks.
3. **Resource constraints**: Design flexible but scaling to truly complex real-world environments (e.g., full Minecraft, realistic robotics) remains future work.
4. **Broader impacts**: LATS improves autonomous decision-making (potential for harmful uses) but enhances interpretability through multiple rounds of linguistic reasoning.

## Relevance to CTRA

LATS is highly relevant to AutoCT's MCTS-based feature engineering architecture (reference [25]):

1. **MCTS architecture foundation**: LATS demonstrates how to adapt MCTS to language agents with text interfaces, directly informing CTRA's Pareto MCTS + adaptive branching (from AB-MCTS, PMMG) approach for multi-objective feature search (accuracy vs. parsimony).

2. **LM-based value function**: LATS's in-context value scoring (prompt LM to evaluate state → 1-10 score) provides an alternative to CTRA's hardcoded Pareto fitness evaluation, enabling semantic understanding of feature quality.

3. **Self-reflection + learning from experience**: LATS's reflection mechanism (store failed trajectories + reflections, integrate as context in future iterations) aligns with CTRA's need to avoid redundant/poor feature configurations in successive MCTS rollouts.

4. **External feedback integration**: LATS shows how to combine internal model knowledge (value function) with external observations (environment feedback), analogous to CTRA integrating agent-engineered features with external trial outcome labels during training.

5. **Exploration-exploitation tradeoff**: LATS's UCT-based exploration weight tuning directly applicable to CTRA's exploration constant in MCTS (e.g., balancing between aggressive feature engineering and conservative reuse of proven features).

6. **Modularity lessons**: LATS's separation of agent, value function, reflection generator suggests CTRA could modularize feature planner, feature engineer, and feature evaluator independently, enabling easier updates to each component.
