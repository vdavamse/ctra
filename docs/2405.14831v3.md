## Abstract

In order to thrive in hostile and ever-changing natural environments, mammalian brains evolved to store large amounts of knowledge about the world and continually integrate new information while avoiding catastrophic forgetting. Despite their impressive accomplishments, large language models (LLMs), even with retrieval-augmented generation (RAG), still struggle to efficiently and effectively integrate a large amount of new experiences after pre-training. In this work, we introduce HippoRAG, a novel retrieval framework inspired by the hippocampal indexing theory of human long-term memory to enable deeper and more efficient knowledge integration over new experiences. HippoRAG synergistically orchestrates LLMs, knowledge graphs, and the Personalized PageRank algorithm to mimic the different roles of neocortex and hippocampus in human memory. We compare HippoRAG with existing RAG methods on multi-hop question answering (QA) and show that our method outperforms the state-of-the-art methods remarkably, by up to 20%. Single-step retrieval with HippoRAG achieves comparable or better performance than iterative retrieval like IRCoT while being 10-20 times cheaper and 6-13 times faster, and integrating HippoRAG into IRCoT brings further substantial gains.

## Problem Statement

Standard RAG encodes each passage **in isolation**. This makes it structurally incapable of tasks that require integrating knowledge *across* passage boundaries — scientific literature review, legal case briefing, medical diagnosis. Iterative retrieval (IRCoT and similar) works around this by running multiple LLM-guided retrieval rounds, but pays for it in latency and API cost, sequentially, per query.

HippoRAG's question: can a **single-step** retrieval achieve multi-hop integration by moving the cross-passage reasoning into an **offline-built graph** and an **online graph-search algorithm**, rather than into repeated LLM calls?

The framing is an analogy to the hippocampal memory indexing theory: the LLM plays neocortex (extracting meaning), the knowledge graph plays the hippocampal index (sparse, associative), and PPR plays pattern completion.

## Key Contributions

1. **A single-step multi-hop retriever** that matches or beats iterative retrieval at 10–30× lower cost and 6–13× lower latency.
2. **Node specificity** — a local, IDF-like term-weighting signal computed from information already present at each node.
3. **Synonymy edges** — embedding-based entity standardization added to the graph, which the authors show matters most on entity-centric datasets.
4. **A thorough ablation** isolating which components actually carry the gains (OpenIE choice, PPR vs. simpler neighbourhood expansion, node specificity, synonymy edges).
5. **Demonstrated complementarity with iterative retrieval** — HippoRAG + IRCoT beats either.

## Methodology / Architecture

### Offline indexing

1. **OpenIE via LLM.** Each passage is processed by an instruction-tuned LLM *L* with a **1-shot prompt**, in two steps: first extract named entities, then feed those entities back into a triple-extraction prompt. The authors report this two-step form "leads to an appropriate balance between generality and bias towards named entities." The result is noun-phrase nodes *N* and relation edges *E*.
2. **Synonymy edges.** A retrieval encoder *M* adds edges *E′* between entity pairs whose cosine similarity exceeds threshold **τ = 0.8**.
3. **The passage matrix.** Indexing yields a **|N| × |P|** matrix **P** counting occurrences of each noun phrase in each original passage.

### Online retrieval

1. Prompt *L* (1-shot) to extract named entities **C_q** from the query.
2. Encode them with *M*; **query nodes R_q** are the graph nodes with highest cosine similarity to each query entity.
3. Run **PPR** over the graph (|N| nodes, |E| + |E′| edges) with a personalization vector giving equal probability to each query node and zero elsewhere. **Damping factor 0.5.**
4. Multiply the resulting node distribution **n′** by **P** to get passage scores.

> The final step — `passage_scores = n′ · P` — is the same projection LinearRAG and SPRIG use. The architectural difference is how the graph got built: HippoRAG pays an LLM per passage; LinearRAG and SPRIG do not.

### Node specificity

Defined as **s_i = |P_i|⁻¹**, where *P_i* is the set of passages node *i* was extracted from. Each query node's probability is multiplied by *s_i* **before** PPR, modulating both its own and its neighbourhood's mass.

The motivation given is neurobiological — true IDF would require a global aggregator neuron touching every node on every retrieval — but the practical content is that this is **an IDF signal computed from purely local information**, which makes it cheap and incrementally updatable.

### Graph scale (Table 1, 1,000-question dev sets)

| | MuSiQue | 2Wiki | HotpotQA |
|---|---|---|---|
| Passages | 11,656 | 6,119 | 9,221 |
| Unique nodes | 91,729 | 42,694 | 82,157 |
| Unique edges | 21,714 | 7,867 | 17,523 |
| Unique triples | 107,448 | 50,671 | 98,709 |
| Contriever synonym edges | 145,990 | 146,020 | 159,112 |
| ColBERTv2 synonym edges | 191,636 | 82,526 | 171,856 |

**Synonymy edges outnumber extracted relation edges by 7–18×.** The graph's connectivity is dominated by embedding similarity, not by the LLM-extracted relations.

### Defaults

GPT-3.5-turbo-1106 (temperature 0) as *L*; Contriever or ColBERTv2 as *M*; τ = 0.8; PPR damping 0.5 — both tuned on 100 MuSiQue training examples. "HippoRAG's performance is rather robust to its hyperparameters."

## Datasets

MuSiQue (answerable), 2WikiMultiHopQA, and HotpotQA — 1,000 validation questions each, with a retrieval corpus built from all supporting and distractor passages following IRCoT. The authors flag that **HotpotQA "has been found to be a much weaker test for multi-hop reasoning due to many spurious signals."** Metrics: recall@2, recall@5, EM, F1.

## Results

### Single-step retrieval (Table 2)

| Method | MuSiQue R@5 | 2Wiki R@5 | HotpotQA R@5 | **Avg R@5** |
|---|---|---|---|---|
| BM25 | 41.2 | 61.9 | 72.2 | 58.4 |
| Contriever | 46.6 | 57.5 | 75.5 | 59.9 |
| GTR | 49.1 | 67.9 | 73.3 | 63.4 |
| ColBERTv2 | 49.2 | 68.2 | **79.3** | 65.6 |
| RAPTOR | 45.3 | 53.8 | 71.2 | 56.8 |
| Proposition (ColBERTv2) | 50.1 | 64.9 | 78.1 | 64.4 |
| **HippoRAG (Contriever)** | 52.1 | **89.5** | 76.2 | **72.6** |
| **HippoRAG (ColBERTv2)** | 51.9 | 89.1 | 77.7 | **72.9** |

The 2Wiki result (68.2 → 89.5, **+21 points**) is the headline. The authors are candid that it "can be partially explained by 2WikiMultiHopQA's entity-centric design, which is particularly well-suited for HippoRAG," and that **HippoRAG loses to ColBERTv2 on HotpotQA** (77.7 vs 79.3).

### Multi-step (Table 3)

IRCoT + HippoRAG (ColBERTv2) reaches avg R@5 **78.2** vs IRCoT + ColBERTv2's 70.0 — the two techniques are complementary, not substitutes.

### Ablations (Table 5, avg R@5)

| Variant | MuSiQue | 2Wiki | HotpotQA | Avg |
|---|---|---|---|---|
| **HippoRAG (full)** | 51.9 | 89.1 | 77.7 | **72.9** |
| REBEL instead of LLM OpenIE | 39.6 | 76.5 | 59.2 | 58.4 |
| Llama-3.1-8B-Instruct | 51.9 | 77.5 | 75.1 | 67.8 |
| Llama-3.1-70B-Instruct | 53.7 | 85.3 | 78.6 | 72.5 |
| **R_q nodes only (no PPR)** | 41.0 | 61.4 | 66.2 | **56.2** |
| **R_q nodes & neighbours (no PPR)** | 38.5 | 74.7 | 64.5 | **59.2** |
| w/o node specificity | 50.2 | 88.8 | 73.7 | 70.9 |
| w/o synonymy edges | 50.2 | 85.6 | 75.7 | 70.5 |

Three findings worth keeping:

- **PPR is doing the work**, not merely the graph: replacing it with query nodes alone drops avg R@5 from 72.9 to 56.2. Notably, **adding one-hop neighbours without PPR is *worse* than using query nodes alone on MuSiQue** (38.5 vs 41.0) — untargeted expansion adds more noise than signal. Principled propagation is the ingredient.
- **Llama-3.1-70B matches GPT-3.5** (72.5 vs 72.9), so the LLM need not be proprietary.
- Node specificity and synonymy edges each contribute ~2 points on average, with opposite dataset profiles (specificity helps MuSiQue/HotpotQA, synonymy helps 2Wiki).

### QA (Table 4)

## Limitations

The authors' own list (§7), plus observations from the tables:

- **Scalability is unvalidated.** "HippoRAG's scalability still calls for further validation… we are yet to empirically prove the efficiency and efficacy of our synthetic hippocampal index as its size grows way beyond current benchmarks." The largest corpus tested is 11,656 passages.
- **Most errors are NER and OpenIE errors** (Appendix F). The graph is only as good as the extraction, and no component is fine-tuned.
- **OpenIE consistency degrades on longer documents** (Appendix F.4).
- **PPR is untyped.** Relations are extracted but then used only as undirected edges; the authors note "several avenues for improvements over simple PPR exist, such as allowing relations to guide graph traversal directly."
- **Indexing cost is the binding constraint** — 10× slower and $15 more per 10,000 passages than the baselines.
- **The 2Wiki result is flattered by dataset design**, as the authors state; HotpotQA, where HippoRAG loses, is also the dataset they note is a weak multi-hop test. The honest summary is that HippoRAG wins decisively where graph structure genuinely matters and not elsewhere.
- **Synonymy edges dominate the graph** 7–18× over extracted edges, which complicates the claim that LLM relation extraction is what makes the method work.

## Relevance to CTRA

1. **The indexing cost table is the quantitative case against LLM-built graphs at CTRA's scale.** $15 and 60 minutes per 10,000 passages with GPT-3.5, or 250 minutes on 4× H100 with Llama-70B. CTRA's corpus spans ClinicalTrials.gov, PubMed, ChEMBL, FAERS, AACT, PrimeKG and Drugs@FDA — millions of passages. Extrapolating the GPT-3.5 figure puts LLM-based graph construction in the **tens of thousands of dollars** and the Llama figure in **H100-months**. On a GTX 1650 Ti it is not on the table at all. This is precisely why LinearRAG and SPRIG exist, and why CTRA vendored the former.

2. **The no-PPR ablation is the best available evidence that CTRA's PPR stage is load-bearing.** Replacing PPR with the query nodes alone costs 16.7 points of avg R@5. More pointedly, **one-hop expansion without PPR is worse than no expansion at all** on MuSiQue. If CTRA ever considers replacing PPR with a cheaper neighbourhood heuristic, this ablation says that specific substitution fails.

3. **Node specificity is a cheap, directly portable improvement.** `s_i = |P_i|⁻¹` needs only each node's passage count — information CTRA's graph already holds. It is worth ~2 points avg R@5 here, requires no model and no extra pass, and is a close cousin of the `specificity_weights` (`1/log(1+cnt)`) already implemented in the user's `schemagraph/graph/ppr.py`. This is listed in `research/linearrag-improvements.md` as an in-place improvement; this paper is its source and its ablation.

4. **Synonymy edges map onto a problem CTRA already has.** HippoRAG adds edges at cosine τ = 0.8 to standardize entities. CTRA faces the same problem in sharper form — drug synonyms across ChEMBL and PubChem, condition names across MeSH and trial free text — but has a **better solution available**: curated synonym tables rather than embedding similarity. HippoRAG's finding that synonymy edges carry the largest single ablation effect on the entity-centric dataset (2Wiki, −3.5) suggests CTRA's curated resolution is a genuine structural advantage, not just a convenience.

5. **The damping factor disagreement is unresolved across the literature.** HippoRAG uses 0.5, SPRIG 0.15, MixPR 0.6. Three papers, three values, each reported as tuned. CTRA should treat this as a parameter requiring local measurement on TREC-CT, not one to copy.

6. **Single-step beats iterative on cost, and both together beat either.** If CTRA later needs stronger multi-hop retrieval, Table 3 says graph retrieval and iterative retrieval compose rather than compete — but Table 17's online costs (IRCoT 20–40 min/1,000 queries) make iteration unattractive inside an agent loop that issues many queries per trial.
