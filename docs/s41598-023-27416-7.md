## Abstract

This study proposes using a machine learning pipeline to optimize clinical trial design. The goal is to predict early termination probability of clinical trials using machine learning modeling, and to understand feature contributions driving early termination. This will inform further suggestions to the study protocol to reduce the risk of wasted resources. A dataset containing 420,268 clinical trial records and 24 fields was extracted from the ClinicalTrials.gov registry. In addition to study characteristics features, 12,864 eligibility criteria search features are used, generated using a public annotated eligibility criteria dataset, CHIA. Furthermore, disease categorization features are used allowing a study to belong to more than one category specified by ClinicalTrials.gov. Ensemble models including random forest and extreme gradient boosting classifiers were used to train and evaluate predictive performance. The study achieved an ROC-AUC score of 0.80 and balanced accuracy of 0.70 on the test set using gradient boosting classification. Shapley Additive Explanations (SHAP) are used to interpret the termination predictions and flag feature contributions.

## Problem Statement

As of 2022, 14.5% of interventional trials recorded in ClinicalTrials.gov terminated prematurely. Clinical trials that fail due to poor study design waste resources and deprive society of data for evaluating potentially effective interventions. The cost of failure is especially large in later phases (Phase 2 and 3) due to larger sample sizes and prior investment. While AI/ML interest in healthcare is growing, it has focused mainly on healthcare delivery rather than clinical research, and existing work has focused on predicting trial outcomes rather than on improving the design of clinical trials. This paper addresses the need for a practical, interpretable ML pipeline that not only predicts early termination but also provides actionable feedback on protocol design features to help clinicians iteratively optimize trial protocols before execution.

## Key Contributions

1. **Enhanced clinical trial dataset** -- Generated an enriched dataset by transforming and integrating two public datasets (AACT from ClinicalTrials.gov and the CHIA annotated eligibility criteria corpus). Created 12,864 eligibility criteria search features (category/entity pairs from CHIA) and disease categorization features allowing multi-label assignment.
2. **Novel eligibility criteria features** -- Used the CHIA dataset (1,000 Phase IV studies with annotated eligibility criteria) to generate binary search features from category-entity pairs (Condition, Procedure, Person, Temporal, Drug, Observation, Mood, Visit), searched against the free-text eligibility criteria field using 5-gram matching. Statistically validated (via McNemar's test, p < 0.01) that these features improve prediction performance.
3. **Interpretable per-protocol predictions** -- Unlike prior work that analyzes feature contributions globally, this pipeline provides individual SHAP-based feature contribution explanations for every new clinical study protocol, enabling iterative protocol optimization.
4. **Clinical trial design optimization pipeline** -- Proposed a three-stage pipeline: (1) Data Preparation and Analytics, (2) ML Pipeline (training and evaluation), (3) Interpret Predictions (SHAP-based iterative protocol refinement loop).

## Methodology / Architecture

### Data Preparation

- **Source:** AACT database (public relational database from CTTI containing ClinicalTrials.gov data), extracted July 6, 2022, containing 420,268 clinical studies.
- **Filtering:** Only interventional studies with settled status (completed, terminated, withdrawn) retained. Studies registered before 2011 removed due to high missing value rates, leaving 112,647 studies (final dataset used for modeling contains studies from 2011--2022).
- **Labeling:** Binary classification -- "success" (completed) vs. "failure" (terminated or withdrawn). The failure rate overall is approximately 15%.

### Feature Engineering

1. **Study characteristics features (24 features):** Logistic, administrative, and design features including number of sites, number of primary/secondary outcomes, randomization, intervention model, intervention type, masking, FDA regulation status.
2. **Disease category features:** Multi-label disease categorization matching ClinicalTrials.gov categories (24 disease categories). A study can belong to multiple categories. Mapped via conditions and MeSH terms. Analysis showed neoplasms and blood/lymph conditions have the highest failure rates.
3. **Eligibility criteria features (12,864 features):**
   - Basic descriptive: healthy volunteer acceptance, gender/age acceptance, number of inclusion/exclusion criteria, total/average word counts.
   - CHIA-derived search features: 12,864 category-entity pairs from the CHIA annotated corpus, searched in the free-text eligibility criteria field using 5-gram language model matching, producing a sparse binary feature matrix.

### Data Processing

- **Missing value imputation:** MICE (Multiple Imputation by Chained Equations) for numerical features.
- **Categorical encoding:** One-hot encoding (handles missing values as zeros).
- **Class imbalance:** Random under-sampling on training set to 1:1 ratio; test set kept imbalanced for realistic evaluation.
- **Feature selection:** Ablation study plotting number of features vs. test error to find elbow point. ANOVA F-score used as scoring function for SelectKBest. Approximately 2,000 features selected as optimal.
- **Train/test split:** 70:30 ratio, with 5-fold cross-validation for model evaluation.

### Models

- **Logistic Regression** -- baseline simpler model
- **Random Forest Classifier** -- ensemble tree-based model
- **XGBoost (Extreme Gradient Boosting)** -- best performing model; hyperparameters tuned via iterative strategy controlling model complexity (max depth, min child weight) and adding randomness (subsampling ratios).

### Interpretation Pipeline

- SHAP force plots for individual predictions flag which features (study design characteristics, eligibility criteria terms, disease categories) contribute positively or negatively to the termination probability.
- If predicted termination probability exceeds a threshold, SHAP interpretation activates, providing clinicians with flagged features to guide protocol edits.
- Iterative process: edit protocol, re-predict, re-interpret until model validates the protocol.

### Statistical Validation of New Features

McNemar's test comparing a model with only study characteristics vs. one that also includes eligibility criteria search features and disease categorization: chi-squared = 97.85, p = 4.504e-23 (p << 0.01), confirming statistically significant improvement.

### SHAP Interpretation Examples (Phase 2 model)

- **Correct Class 1 prediction:** Number of countries, inclusion criteria count, and specific exclusion criteria (Condition/inflammation, Condition/dry eye) contributed positively; exclusion-Temporal/active and non-acceptance of healthy volunteers contributed negatively.
- **Correct Class 0 prediction:** Number of countries, specific eligibility feature, and FDA regulation status pushed toward failure; blood/lymph conditions, inclusion count, and number of facilities pushed toward success.
- **Incorrect prediction example:** Some eligibility criteria features had non-intuitive contributions (e.g., Inclusion--Mood/confirmed, Inclusion--Person/age), illustrating room for improvement in eligibility criteria feature engineering.

## Limitations

- **CHIA dataset coverage:** CHIA is annotated from only 1,000 Phase IV studies, which may not cover all eligibility criteria categories and entities relevant to earlier-phase studies. Some generated search pairs are not intuitive.
- **Eligibility criteria feature engineering is preliminary:** The 5-gram search approach is computationally efficient but may miss semantic nuances. More sophisticated NLP processing could yield better features.
- **Binary labeling only:** Unlike Ferdowsi et al. (2023), this study uses only binary completed/failed labeling, which does not capture the spectrum of risk (e.g., completed trials that still had major protocol issues).
- **No deep learning or transformer-based text models:** The approach relies on sparse binary search features rather than contextual embeddings for the eligibility criteria text.
- **Missing values in historical data:** Despite filtering to post-2011 records, data quality issues persist in the registry.

## Relevance to CTRA

This paper is directly relevant to the CTRA project's goal of predicting protocol uninformativeness:

- **Same core prediction task:** Predicting early termination from protocol design features is closely aligned with predicting protocol uninformativeness. Many of the same factors (poor enrollment criteria, inadequate site selection, suboptimal outcome measure design) lead to both termination and uninformative results.
- **Eligibility criteria as predictive features:** The novel use of CHIA-derived eligibility criteria search features demonstrates that the content of inclusion/exclusion criteria (not just their count) carries predictive signal. CTRA could adopt or extend this approach, potentially with more sophisticated NLP, to identify eligibility criteria patterns associated with uninformativeness.
- **Disease category risk profiles:** The disease categorization analysis (neoplasms and blood/lymph conditions have highest failure rates) provides useful priors for CTRA models.
- **Iterative protocol optimization pipeline:** The proposed three-stage pipeline (predict, interpret with SHAP, edit protocol) directly maps to CTRA's goal of providing actionable feedback to protocol designers. The per-prediction SHAP interpretation is more useful than global feature importance for individual protocol review.
- **Practical, lightweight approach:** Unlike deep learning approaches, the XGBoost + SHAP pipeline is fast, interpretable, and deployable, which is important for CTRA's intended use as a protocol review tool.
- **Complementary to Ferdowsi et al.:** While Ferdowsi et al. (2023) uses deep learning on protocol text structure, this paper demonstrates that classical ML with carefully engineered features (including novel eligibility criteria features) can achieve competitive performance with greater interpretability.
