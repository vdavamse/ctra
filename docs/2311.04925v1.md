## Abstract

Benchmarking drug efficacy is a critical step in clinical trial design and planning. Much of the data on efficacy endpoints is stored in scientific papers in free text form, making extraction currently a largely manual task. The authors developed and optimized a framework to extract efficacy endpoints from text in scientific papers using a machine learning approach. Their machine learning model predicts 25 classes associated with efficacy endpoints and achieves high F1 scores of 96.4% on the test set, and 93.9% and 93.7% on two real-world case studies. These methods were evaluated against subject matter experts and show significant promise for automating the extraction of clinical endpoints from free text.

## Problem Statement

Benchmarking the efficacy of a new drug against existing drugs is essential for trial planning and design. However, **most efficacy data appears as unstructured text** in clinical trial reports and scientific journal articles. Currently, extracting this data requires **laborious manual reading** of papers to find relevant numerical results (e.g., overall survival, progression-free survival, response rates).

This manual extraction process:
- Does not scale with the increasing volume of published literature
- Is prone to human error
- Creates bottlenecks in clinical trial design timelines

The challenge is to **automate the extraction of specific oncology efficacy endpoints and their associated numerical values** from scientific literature at high accuracy.

## Key Contributions

1. **End-to-end framework for efficacy endpoint extraction:** Combined rule-based information retrieval (i2e queries on MEDLINE) with deep-learning NER to extract 25 classes of oncology efficacy endpoints from scientific papers.
2. **Fine-grained entity classification:** Defined a 25-class NER schema that distinguishes endpoints not just by type (OS, PFS, ORR, DFS, DoR) but also by expression format (duration vs. percentage) and confidence interval bounds (CIL, CIH), plus time points.
3. **Dataset generation methodology:** Demonstrated an effective approach for creating ML training data by using rule-based i2e queries on MEDLINE to retrieve and pre-highlight relevant sentences, followed by manual correction and annotation.
4. **Model selection and evaluation:** Compared four BERT-variant models (BERT, DistilBERT, BioBERT, PubMedBERT) and selected BioBERT as the best performer with an overall F1 of 96.4%.
5. **Real-world validation:** Evaluated on two independent case studies representative of actual literature review workflows, achieving 93.9% and 93.7% F1 respectively.

## Methodology / Architecture

### Pipeline Overview

The framework consists of three stages: (1) dataset generation, (2) model development, and (3) model evaluation on case studies.

### Stage 1: Dataset Generation and Annotation

**Information retrieval using i2e:**
- i2e (by Linguamatics/IQVIA) is a rule-based query language that searches an index of MEDLINE
- Ensemble of queries built per endpoint, designed by linguistic experts to capture diverse sentence constructions
- Queries pre-highlight numerical values to assist manual labellers
- Negative training samples deliberately included (e.g., "age" confused with survival, "LOS" confused with OS, standard deviations confused with confidence intervals)

**Entity Schema -- 25 classes derived from 6 base endpoints:**

| Base Endpoint | Abbreviation | Variants |
|---|---|---|
| Overall Survival | OS | OS, OS_percent, OS_CIL, OS_CIH, OS_percent_CIL, OS_percent_CIH |
| Progression Free Survival | PFS | PFS, PFS_percent, PFS_CIL, PFS_CIH, PFS_percent_CIL, PFS_percent_CIH |
| Overall Response Rate | ORR | ORR, ORR_CIL, ORR_CIH |
| Disease Free Survival | DFS | DFS, DFS_percent, DFS_CIL, DFS_CIH, DFS_percent_CIL, DFS_percent_CIH |
| Duration of Response | DoR | DoR, DoR_CIL, DoR_CIH |
| Time Point | time_point | time_point |

**Labelling process:**
- Two independent clinical information subject matter experts labelled each sentence using Label Studio
- Disagreements reviewed and reconciled
- Post-reconciliation agreement: 99.7--99.9% across all datasets

### Stage 2: Machine Learning Model

**Task:** 25-class NER problem using BIO tag scheme.

**Models evaluated:**
- BERT (base, trained on Wikipedia + BooksCorpus)
- DistilBERT (compressed BERT, 95% performance, 2x faster)
- BioBERT (BERT fine-tuned on PubMed + PMC biomedical corpora)
- PubMedBERT (trained from scratch on PubMed + PMC)

**Training procedure:**
- Tokenization via Hugging Face AutoTokenizer
- Fine-tuned on pre-trained weights
- Grid search over 18 hyperparameter combinations
- 5-fold cross-validation
- Code adapted from Hugging Face library

**Optimal hyperparameters (same for all models):**
- Epochs: 4
- Learning rate: 5e-5
- Batch size: 16

### Stage 3: Case Study Evaluation

- Two real-world literature searches requiring efficacy endpoint extraction
- Case Study 1: 70 abstracts/full texts
- Case Study 2: 37 abstracts/full texts
- Sentence selection via high-recall i2e query + fine-tuned BERT model
- Independent labelling by both annotators, then reconciliation
- Model predictions compared against reconciled labels

### Handling Complex Sentence Patterns

The paper identifies several challenging linguistic constructions:
- **"Respectively" constructions:** Lists of endpoints paired with lists of values (e.g., "3-, 5- and 10-year survival rates were 45%, 40% and 35%, respectively")
- **Comparison constructions:** Pairs separated by "than" or "versus" (e.g., "OS was significantly longer in the experimental group than in the control group (median 14.1 months vs 10.7 months)")
- **Nested combinations:** Multiple endpoints with multiple time points and multiple reporting groups in a single sentence

## Results

### Model Comparison (5-fold cross-validation on training data)

| Model | F1 | Precision | Recall | Time (s) |
|---|---|---|---|---|
| BERT | 95.1% | 94.9% | 95.2% | 513 |
| DistilBERT | 93.3% | 93.3% | 93.2% | 275 |
| **BioBERT** | **96.4%** | **96.2%** | **96.6%** | 482 |
| PubMedBERT | 96.4% | 96.3% | 96.5% | 508 |

BioBERT selected as best model (marginally better than PubMedBERT, significantly better than base BERT/DistilBERT).

### Test Dataset Performance (BioBERT, averaged across two labellers)

- **Overall F1:** 96.4%
- **Overall Precision:** 96.0%
- **Overall Recall:** 96.8%
- Most individual endpoint F1 scores > 90%; all > 85%
- Highest: DoR_CIL (100%), PFS_CIL (98.4%), PFS_CIH (98.3%), OS_CIL (98.3%)
- Lowest: ORR (84.7%), PFS_percent_CIL (85.7%)

### Case Study Performance (BioBERT)

| Metric | Case Study 1 | Case Study 2 |
|---|---|---|
| Overall F1 | 93.9% | 93.7% |
| Overall Precision | 94.2% | 95.2% |
| Overall Recall | 93.6% | 92.3% |

- Most endpoint F1 scores > 85%
- Lower scores observed for rare endpoints with few instances (e.g., PFS_percent_CIH/CIL: 62.5% F1 in Case Study 1 with only 11 instances; OS_percent: 66.7% F1 in Case Study 2 with only 5 instances)

## Limitations

1. **Limited endpoint coverage:** Only 6 base oncology endpoints (OS, PFS, ORR, DFS, DoR, time_point); the changing landscape of clinical development may require additional endpoints (e.g., event-free survival, pathological complete response).
2. **Adding new endpoints is cumbersome:** The entire training dataset needs to be relabelled for each new endpoint, though cascading models is proposed as a workaround.
3. **Oncology-specific:** The model was trained exclusively on oncology literature and may not generalize to other therapeutic areas.
4. **No cohort/treatment group identification:** The model extracts endpoint values but does not identify which patient population or treatment arm the value corresponds to (addressed separately in other work).
5. **Class imbalance:** Rare endpoints and confidence intervals have fewer training examples and correspondingly lower performance.
6. **Sentence-level extraction only:** The model operates on individual sentences and does not capture cross-sentence relationships or document-level context.
7. **Requires SME review:** The model is designed as a human-in-the-loop tool; outputs are reviewed and validated by subject matter experts rather than used autonomously.
8. **No public code/model release:** No public repository is mentioned for the trained models or code.

## Relevance to CTRA

This paper relates to the CTRA project in several important ways:

- **Endpoint extraction for protocol assessment:** CTRA predicts protocol uninformativeness, and one key aspect of a well-designed protocol is the specification of appropriate efficacy endpoints. This paper's NLP pipeline for extracting and classifying endpoints (OS, PFS, ORR, DFS, DoR) could be adapted to **automatically identify what endpoints a protocol specifies** and compare them against standards for the therapeutic area.
- **Benchmarking and competitive landscape analysis:** For CTRA to assess whether a trial protocol is likely to be uninformative, it helps to know what efficacy benchmarks exist for the same indication. This paper's extraction framework can **automatically build a landscape of published efficacy results** for a given disease/drug class, which CTRA could use as contextual features (e.g., if a protocol's target endpoint is already well-established as ineffective in prior literature).
- **Methodology for clinical NLP at AstraZeneca/IQVIA:** The paper comes from AstraZeneca and Linguamatics (IQVIA), demonstrating the industry's investment in NLP for clinical trial design. The i2e + BERT pipeline illustrates a practical production-ready approach that CTRA could adopt for its own text extraction needs.
- **BERT model selection insights:** The comparison of BERT, DistilBERT, BioBERT, and PubMedBERT on clinical NER is directly informative for CTRA's model choices. BioBERT's marginal advantage over PubMedBERT, and DistilBERT's 2x speed advantage with only 3.1% F1 drop, are useful engineering tradeoffs.
- **Handling complex sentence patterns:** The paper's detailed analysis of "respectively" constructions and comparison patterns in clinical text is relevant to any NLP work on trial protocols and reports, including CTRA.
- **Different focus from CTRA's core task:** This paper extracts **efficacy results** from published literature (post-hoc), whereas CTRA assesses **protocol design quality** pre-trial. However, the extracted efficacy data could serve as external context features for CTRA (e.g., historical efficacy benchmarks for the same indication).
